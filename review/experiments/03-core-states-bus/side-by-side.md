## What the drivers do before the model sees the input

* `Exe/CoreStates.lean`: `Json.parse` (Lean core). Numbers become `JsonNumber` (mantissa, decimal exponent ≥ 0): float-ness survives only as "has fraction digits"; `-0.0` becomes `0.0`; `NaN`/`Infinity` do not parse (the line is answered `unsupported` with the parser's message, e.g. `offset 68: unexpected input`). Objects become key-sorted trees. `force_update`: only a JSON bool is read. `attributes`: object or null, anything else `unsupported`. `context`: needs a non-empty string `id`; `{}` is `unsupported` (the shipped harness treats `{}` as "no context" on the HA side, `_ctx`: `if not c: return None`, so an empty context mapping in a case would be a harness artefact; no case uses it).
* `Exe/CoreEvents.lean`: same parser. Output is printed with Lean's `Json.compress`, which drops a float's trailing `.0`; the harness compares with plain `==`, so number types in event data are not compared.
